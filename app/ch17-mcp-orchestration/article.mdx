<DropCap>

An agent is only as capable as the things it can reach. A model that can reason brilliantly but cannot run a query, read a document, or post a message is a very expensive autocomplete. So the real engineering of agentic analytics is plumbing: how the agent connects to the firm's data and tools, how multiple agents coordinate, and how the whole thing keeps running when something fails. In barely eighteen months this plumbing went from a tangle of one-off integrations to a recognizable, layered stack — and understanding that stack is how a manager tells a durable platform decision from a fad.

</DropCap>

## Tool use: the atom

At the bottom of everything is **tool use**, also called function calling. The developer describes a tool to the model — a name, a description, and a JSON schema for its inputs — and the model, when it decides the tool is needed, emits a structured call that the surrounding code executes. &ldquo;Run this SQL,&rdquo; &ldquo;search these docs,&rdquo; &ldquo;send this message&rdquo; are all tool calls. Everything above is a way of organizing tool calls at scale.

## MCP: the USB-C moment

The problem with tool use was that every assistant needed a custom connector for every system — an `N×M` explosion of bespoke integrations. Anthropic's **Model Context Protocol (MCP)**, open-sourced in November 2024, standardized that connection. Its own documentation offers the analogy that stuck: MCP is &ldquo;a USB-C port for AI applications&rdquo; — build a tool once, and any MCP-speaking client can use it.<Cite id="mcp-anthropic" sources={sources} /><Cite id="mcp-intro" sources={sources} />

What turned a single vendor's proposal into infrastructure was adoption. OpenAI embraced MCP in March 2025 — Sam Altman wrote, &ldquo;People love MCP and we are excited to add support across our products&rdquo;<Cite id="openai-mcp" sources={sources} /> — followed by Google and Microsoft. By its first anniversary the MCP registry held close to 2,000 servers, with adopters spanning GitHub, OpenAI, Microsoft, AWS, and Google Cloud,<Cite id="mcp-year" sources={sources} /> and Google had begun shipping fully managed remote MCP servers for BigQuery and other services.<Cite id="google-mcp" sources={sources} /> A standard that every major lab supports is no longer a bet; it is a foundation.

## Above the wire: A2A and orchestration

If MCP is how an agent reaches *tools and data*, the **Agent2Agent (A2A) protocol** is how agents reach *each other*: a standard, contributed to the Linux Foundation in June 2025 with more than a hundred supporting companies, that lets independent agents from different vendors discover one another and delegate work.<Cite id="a2a" sources={sources} /> Above the protocols sit **orchestration frameworks** that sequence multi-step, multi-agent work — LangGraph, OpenAI's Agents SDK (launched March 2025 with tools, handoffs, guardrails, and tracing), Google's Agent Development Kit, Microsoft's Agent Framework, and CrewAI among them.<Cite id="openai-sdk" sources={sources} /><Cite id="google-adk" sources={sources} /><Cite id="ms-agent" sources={sources} /><Cite id="langgraph" sources={sources} /><Cite id="crewai" sources={sources} />

## Durable execution: why agents need it

Agent runs are long, branchy, and failure-prone: a model can be probabilistic, a tool can time out, a human approval can take a day. Ordinary retry logic does not survive that. **Durable-execution** engines — Temporal, Inngest, Restate, Vercel's Workflow Development Kit — solve it by persisting workflow state at every step and replaying after a crash, so a multi-day agentic pipeline resumes exactly where it stopped. The market is voting with capital: Temporal raised a $300 million round at a $5 billion valuation in early 2026, explicitly to &ldquo;make agentic AI real for companies,&rdquo; with OpenAI and Block among its named customers.<Cite id="temporal-d" sources={sources} /> Durable execution is becoming table stakes for any agent that touches production.

## The catch: every tool is an attack surface

The same property that makes MCP powerful — agents can be handed new tools freely — makes it dangerous. A tool's description is text the model trusts, which means it is a place to hide malicious instructions; an over-permissioned agent connected to private data and the open internet is a breach waiting to happen.<Cite id="willison-mcp" sources={sources} /> The plumbing chapter ends where the next one begins: connectivity without governance is a liability, not a feature.

<Pitfall title="Connecting an agent to everything">
The easiest way to make an agent useful is to give it broad access; the easiest way to cause an incident is the same move. **Scope each MCP connection to the minimum data and actions the task requires, treat tool descriptions as untrusted input, and never wire an agent to private data and an outbound channel without a human gate in between.** Convenience and least-privilege pull in opposite directions — and on a system that touches the warehouse, least-privilege has to win.
</Pitfall>

<Takeaway label="What to build on">

The agentic stack has stabilized into layers: tool use is the atom; MCP standardizes governed access to data and tools; A2A lets agents collaborate; orchestration frameworks sequence the work; and durable execution keeps it alive through the real world's failures. For a platform decision, favor the layers that the whole industry now shares — MCP, A2A, a major orchestration framework, a durable-execution engine — because interoperability is what protects you from lock-in. And remember that every connection you add is also an attack surface, which is why governance ([§17.5](/ch17-agent-governance)) is not optional.

</Takeaway>
